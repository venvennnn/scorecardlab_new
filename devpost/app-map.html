ScorecardLab

A browser page for a monotonic Weight-of-Evidence scorecard. The dataset stays in memory. The TypeScript engine bins it. React draws the result.

Reference route, not a tour that was walked live:

  1. src/ui/WoeChart.tsx — startDrag turns the pointer into a feature value.
  2. src/engine/binning.ts — projectRanges picks the nearest strictly monotonic partition that meets the minimum bin size.
  3. src/engine/scorecard.ts — dragCut rebuilds points and the KS summary the ledger shows.

To change this, start here

  • Defaults for PDO, base score, odds, and the 5% minimum bin: DEFAULT_SETTINGS in src/engine/types.ts.
  • The points formula: allocatePoints in src/engine/stats.ts.
  • Colors and type: tailwind.config.js, copied from the visual reference tokens.

A practice to reuse

The drag is specified as “the event-rate sequence stays strictly monotonic” in devpost/prd.md, and src/engine/metrics.test.ts checks a bad cut comes back monotonic. Naming the visible result made the projection testable without looking at the chart.

Run it again with npm install and npm run dev, then open the URL Vite prints. This map is a snapshot of the source and can drift.
